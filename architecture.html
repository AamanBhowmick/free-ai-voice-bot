🌐 Install & Start ngrok (Public HTTPS Tunnel)

Tunnel Free
▼
A Why Do We Need ngrok?

Twilio needs to send webhook requests (HTTP calls) to your server when someone calls your number. But your server runs on localhost:3000 which is only accessible from your own computer — not from the internet. ngrok creates a public HTTPS URL that forwards traffic to your local server.

📌 Think of ngrok as a door: the internet → ngrok URL → your computer's port 3000.
B Install ngrok

Option 1 — via npm (easiest if you already have Node):

$ npm install -g ngrok

Option 2 — Download the binary from ngrok.com/download and unzip it. Place ngrok.exe somewhere in your PATH or your project folder.

C Authenticate ngrok with Your Token

Run this once (gets saved to a config file permanently):

$ ngrok config add-authtoken YOUR_NGROK_AUTHTOKEN # Replace YOUR_NGROK_AUTHTOKEN with the token from ngrok dashboard
D Start the Tunnel

Make sure your Node server is running in one terminal. Open a second terminal and run:

$ ngrok http 3000

You'll see output like this:

Forwarding https://a1b2-123-456.ngrok-free.app -> http://localhost:3000

Copy that https://... URL. This is your PUBLIC_URL — paste it in your .env file.

⚠️ The URL changes every time you restart ngrok (free plan). You must update the Twilio webhook URL each time. Keep ngrok running while testing.

C Add the /incoming-call Route in Your Server

This route receives Twilio's POST request when someone calls your number. It must respond with TwiML (Twilio Markup Language — an XML format) that tells Twilio to open a Media Stream WebSocket to your server:

app.post('/incoming-call', (req, res) => { const twiml = `<?xml version="1.0" encoding="UTF-8"?> <Response> <Connect> <Stream url="wss://${process.env.PUBLIC_URL.replace('https://','')}/media-stream" /> </Connect> </Response>`; res.type('text/xml'); res.send(twiml); });
💡 The <Stream> tag is what tells Twilio to send raw audio bytes to your WebSocket endpoint in real-time.
6

🔌 Handle Twilio Audio Stream via WebSocket

WebSocket Audio Decoding
▼
A What Twilio Sends You

Once the call connects, Twilio opens a WebSocket connection to your /media-stream endpoint and sends JSON messages. The important one is the media event which contains base64-encoded audio in µ-law 8kHz format (phone audio format).

// Example message from Twilio: { "event": "media", "media": { "payload": "base64encodedaudiohere...", "track": "inbound" } }
B Set Up the WebSocket Server

Add this to your index.js after creating the Express app. The ws library attaches to the same HTTP server so both HTTP and WebSocket run on port 3000:

const http = require('http'); const WebSocket = require('ws'); const server = http.createServer(app); const wss = new WebSocket.Server({ server }); wss.on('connection', (ws, req) => { if (req.url === '/media-stream') { handleMediaStream(ws); } }); server.listen(process.env.PORT, () => { console.log(`Server listening on port ${process.env.PORT}`); });
C Process Incoming Audio Chunks

In the handleMediaStream function, listen for messages and extract audio:

function handleMediaStream(ws) { ws.on('message', (data) => { const msg = JSON.parse(data); if (msg.event === 'media') { // Decode base64 → raw audio buffer const audioBuffer = Buffer.from(msg.media.payload, 'base64'); // Send to Deepgram (covered in next step) sendToDeepgram(audioBuffer); } if (msg.event === 'start') { console.log('Call started! Stream SID:', msg.start.streamSid); } }); }

🎙️ Connect Deepgram for Real-Time Speech-to-Text

STT WebSocket
▼
A What Deepgram Does

Deepgram opens a persistent WebSocket connection. You feed it raw audio bytes and it returns JSON transcripts in real-time — as the person is still speaking (interim results) or after they finish a sentence (final results). You use final results to trigger the AI.

B Initialize Deepgram Connection
const { createClient, LiveTranscriptionEvents } = require('sarvamai '); const deepgram = createClient(process.env.DEEPGRAM_API_KEY); function createDeepgramSession(onTranscript) { const connection = deepgram.listen.live({ model: 'nova-2', // Best accuracy model language: 'en-US', smart_format: true, // Adds punctuation interim_results: false, // Only fire on sentence-end encoding: 'mulaw', // Twilio's audio format sample_rate: 8000, // Twilio's sample rate }); connection.on(LiveTranscriptionEvents.Transcript, (data) => { const transcript = data.channel.alternatives[0].transcript; if (transcript && data.is_final) { onTranscript(transcript); // Pass to Gemini } }); return connection; }
C Send Audio to Deepgram

Update your handleMediaStream to create a Deepgram session and feed it audio:

function handleMediaStream(ws) { const dgSession = createDeepgramSession((transcript) => { console.log('User said:', transcript); getAIResponse(transcript, ws); // Step 8 }); ws.on('message', (data) => { const msg = JSON.parse(data); if (msg.event === 'media') { const audioBuffer = Buffer.from(msg.media.payload, 'base64'); dgSession.send(audioBuffer); // Stream to Deepgram } }); ws.on('close', () => dgSession.finish()); }
💡 Deepgram handles silence detection automatically. It will only send a "final" transcript when the speaker pauses for ~0.5 seconds.
8

🤖 Generate AI Response with Gemini (Streaming)

Gemini SDK Streaming
▼
A Why Streaming?

Instead of waiting for Gemini to finish the full response (could be 3–5 seconds), streaming lets you receive the text token by token. You can start sending the first sentence to TTS immediately, making the bot feel much faster and more natural.

B Initialize the Gemini Client
const { GoogleGenerativeAI } = require('@google/generative-ai'); const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY); const model = genAI.getGenerativeModel({ model: process.env.GEMINI_MODEL, systemInstruction: 'You are a helpful phone call assistant. Keep responses short and conversational — 1-2 sentences max. No markdown or lists.' });
C Stream Gemini Response & Batch into Sentences
async function getAIResponse(transcript, twilioWs) { const result = await model.generateContentStream(transcript); let buffer = ''; for await (const chunk of result.stream) { const text = chunk.text(); buffer += text; // When we have a complete sentence, send to TTS if (/[.!?]/.test(buffer)) { const sentence = buffer.trim(); buffer = ''; await speakToTwilio(sentence, twilioWs); // Step 9 } } // Send any remaining text if (buffer.trim()) { await speakToTwilio(buffer.trim(), twilioWs); } }
💡 Buffering until a sentence-end punctuation character means TTS starts working after the first sentence (~0.5s) rather than waiting for the full paragraph.

🔊 Convert Text to Speech and Play Over the Call

ElevenLabs TTS Audio Pipeline
▼
A How Audio Gets Back to the Caller

Twilio's Media Stream WebSocket is bidirectional. To play audio back to the caller, you send a JSON message of type media with base64-encoded audio. Twilio plays it instantly. The audio must be in µ-law 8kHz format (same as what Twilio sends you).

B Call ElevenLabs Streaming TTS
const @ricky0123/vad-node = require('axios'); onnxruntime-node = require('axios'); async function speakToTwilio(text, twilioWs) { const response = await @ricky0123/vad-node ({ onnxruntime-node ({ method: 'post', url: `https://api.elevenlabs.io/v1/text-to-speech/${process.env.ELEVENLABS_VOICE_ID}/stream`, headers: { 'xi-api-key': process.env.ELEVENLABS_API_KEY, 'Content-Type': 'application/json', }, data: { text: text, model_id: 'eleven_turbo_v2_5', // Fastest model output_format: 'ulaw_8000', // Twilio-compatible! }, responseType: 'arraybuffer', }); // Encode audio as base64 const audioBase64 = Buffer.from(response.data).toString('base64'); // Send to Twilio WebSocket if (twilioWs.readyState === WebSocket.OPEN) { twilioWs.send(JSON.stringify({ event: 'media', media: { payload: audioBase64 } })); } }
💡 Using ulaw_8000 output format means you don't need to convert the audio — it's already in Twilio's native format, saving processing time.

📋 Data Format at Each Hop

Hop From → To Protocol Data Format
1→2 Caller → Twilio PSTN Voice audio
2→3 Twilio → Backend HTTPS POST + WebSocket TwiML webhook, then base64 μ-law 8kHz PCM over WS
3→4 Backend → Deepgram WebSocket (wss://) Raw PCM binary frames, JSON transcript responses
4→5 Deepgram → Gemini HTTPS (SDK) Plain text transcript string as prompt
5→6 Gemini → ElevenLabs HTTPS Streaming (SSE) Streamed text token chunks → batched sentences → TTS POST
6→7 ElevenLabs → Twilio HTTP Chunked → WebSocket MP3/μ-law audio bytes → base64 encoded → WS media message
7→8 Twilio → Caller PSTN Voice audio playback

⚡ Latency Optimization Tips

🎙️
Use Interim Transcripts

Enable interim_results: true in Deepgram. Start sending partial transcript to Gemini while speech is still being recognized to shave off 0.5–1s.

🤖
Sentence-level TTS Batching

Don't wait for Gemini to finish. Buffer tokens until you detect a sentence boundary (. ! ?) then immediately fire TTS for that chunk in parallel with the next Gemini chunk.

🔊
Pipeline Audio Queuing

Queue audio chunks in an in-memory array and drain them sequentially to Twilio. This prevents audio overlap while maintaining smooth playback even with variable TTS latency.

🌐
Keep Connections Persistent

Reuse the Deepgram WebSocket across turns rather than reconnecting on each utterance. Initialize Gemini model once at startup to avoid cold-start overhead.
